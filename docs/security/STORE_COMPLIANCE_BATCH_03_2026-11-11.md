## الإصلاحات الفعلية: 4
1. P0: إلغاء التسجيل يستخدم cancel_incomplete_registration_atomic بدلاً من حذف عام اعتماداً على نسخة ملف قديمة. الخادم يقفل صف المستخدم، يعيد فحص عدم اكتمال التسجيل، ويحتفظ بجميع حواجز delete_user_permanently المالية والتشغيلية. NULL للحالة يرفض بأمان، والحذف لحساب آخر مرفوض حتى عبر هذا المسار بحساب إداري.
2. P0: إزالة محاولة الحذف العام الاحتياطية عند خطأ الشبكة. الرد الغامض أو فشل الاتصال لا يبرران طلباً أشد تدميراً.
3. P1: إكمال تسجيل المالك يتطلب success=true صراحة، ويرفض اختلاف معرف الملف عن هوية المستخدم. تنقيح رسائل السجل من استجابة الخادم الخام.
4. P0: mark_chat_messages_as_read يتحقق من عضوية المحادثة قبل لمس الرسائل، ويقفل المحادثة ويحدث عداد المستخدم وحده من القيمة الحالية. الطلب المكرر آمن. service_role أيضاً لا يعلّم القراءة باسم شخص غير مشارك.

## التحقق
- تنفيذ اختبارات الخادم فوراً قبل النشر داخل معاملة ROLLBACK: نجحت 17 حالة/تحقق، بأدوار anon/authenticated و5 حسابات اصطناعية فقط.
- تغطية: رفض مجهول/هوية غائبة/حساب آخر/حالة إكمال مجهولة أو مكتملة/مديونية، نجاح الحذف الفعلي لحساب غير مكتمل، منع غير المشاركين وانتحال مشارك، عدم تغير البيانات عند الرفض، نجاح القراءة وتكرارها وعزل العدادات.
- نشر migration على vsp-staging فقط (vtwgqyxglevcsxwdmhop): نجح. إعادة الاختبار بعد النشر والمستشار: قيد التحقق عند هذا commit.
- إضافة 8 حالات Flutter جديدة: فشل الشبكة بلا حذف احتياطي، 6 استجابات إكمال المالك، اختلاف هوية الملف. الملف يحتوي الآن 16 حالة، منها 8 موجودة سابقاً.
- Flutter analyze/full suite وAndroid: قيد التشغيل بعد هذا commit؛ لا يعد نجاح التشغيل القديم نجاحاً لهذا التعديل.
- خطأ محلي أثناء تركيب استعلام الاختبار: استبدال JavaScript لـ$$ إلى$؛ صحح قبل تشغيل الاختبارات، ولم يطبق أي تغيير دائم به.
- أداة CLI v2.81.3 أنشأت اسم migration محلياً؛ لا ترقية SDK أو CLI إلى v3.
- مصدر الدالة الأصلية على staging يتضمن حواجز مالية أوسع من migration القديم؛ لذلك لم يستبدل جسم الحذف العام.
