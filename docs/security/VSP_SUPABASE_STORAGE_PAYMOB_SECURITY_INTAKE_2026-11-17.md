## Paymob — existing tasks reused (NO duplicate new task)
- Covered by existing **30.02–30.08, 45.04/45.07, 62.*, 63.*, 64.*, 77–80 and SEC-06/SEC-10**. The recent accepted financial SQL/Flutter tests and existing partial unique Paymob transaction index are cited in `docs/VSP_VERIFIED_PAYMOB_AND_ARABIC_PAYMENT_RLS_ACCEPTANCE_2026-11-17.md`; they **do not** demonstrate a live gateway, real refund, cross-account JWT or full event-reordering test.
- **Confirmed source issue (P1, local remediation committed)**: before HMAC authorization, webhook rejection logging stored raw invalid/missing-signature payloads, full `req.url` including `hmac` query value on malformed JSON, and the received HMAC on a mismatch. Production `paymob_webhook` v45 was read-only inspected and still contains `rawUrl` and `receivedHmac` patterns; the branch patch **has not been deployed**. Do not log signed URL/query, full untrusted payment bodies or digest values.
- **Code remediation only on branch**:
  - `supabase/functions/_shared/paymob_hmac.ts`: documented 20-field SHA-512, fixed 128-position hex comparison.
  - `supabase/functions/paymob_webhook/index.ts`: remove raw URL and unverified payload/signature log content; use shared comparator, strict `success === true && pending === false`, preserve verified payload and authoritative payment RPC to avoid breaking accounting consumers.
  - `supabase/functions/tests/paymob_hmac_test.ts` and `.github/workflows/financial-payment-regressions.yml`: isolated synthetic vectors, bad/missing/tampered signatures, and pre-auth audit-source guard. Workflow must pass on **current SHA** before acceptance.
- Open follow-up: verified-payload logs may contain PII; review every `webhook_logs.payload` reader before changing this record format. Check late/duplicate/refund/webhook order with isolated transactions and actual staging integration; no real money. Verify exact `paymob_order_id` required on all order types before considering a stricter fail-closed migration (legacy null order IDs and consumers may exist). Review `create_paymob_intention` provider-error logging for unredacted response data. Never expose signing secrets or merchant keys.
