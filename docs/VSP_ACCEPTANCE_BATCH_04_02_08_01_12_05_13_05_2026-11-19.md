### 04.02 — Translation key completeness (bounded)
The audit of 563 non-generated Dart files and two ARB catalogs found **756 Arabic / 756 English keys, zero missing in either language, zero placeholder mismatches, zero blank values**. The source scanner also flags **33 literal `Text(...)` candidates** (9 Latin/24 Arabic); these remain candidates for manual UI-language verification under **04.06 / 04.07**, not a claim that every onscreen string is localized. No new keys needed to reconcile the currently declared dictionaries.

### 08.01 — First registration steps audited (review only)
**Read in source on the evidence revision:**
- `lib/features/auth/screens/select_role_screen.dart`: role selection is sent into `AuthProvider.setUserType` and account-switching goes through sign-out first
- `lib/features/auth/screens/signup_screen.dart`: separate player/owner form mode, names, phone, email, password/confirmation, birth date and consent; `SignupValidationService.validateForm` runs before the provider create-account action
- `lib/features/auth/screens/player_onboarding_screen.dart`: account profile completion after identity, including position, governorate and DOB/terms; local callback guards
- `lib/features/auth/screens/owner_onboarding_screen.dart`: owner profile completion and navigation into venue setup; location and registration-state handling
- `test/features/auth/signup_full_form_widget_test.dart` and signup validation tests cover form-level behavior; not a real OAuth or SMS session

**Findings and next steps:** parallel initial registration and post-auth onboarding are intentionally different entry contexts, not interchangeable; avoid duplicating fields without a verified handoff. The automatic location step in `signup_screen.dart` currently logs a raw caught error through `debugPrint`; this needs a privacy-safe review before production (not marked fixed here). **08.02** is still open for field rationalization; **08.05** for pause/resume; **08.06** for measured completion; **11.04**, **19.06** and role/staging account journeys stay open. **08.01** records the completed audit, not a completed registration funnel or UI redesign.

### 12.05 — Profile-save client verification (bounded)
`EditProfileScreen` validates name and phone; for players, validates the selected position code, sends only allowed editable fields and does not send role/UID. Dedicated widget tests in Arabic and English verify success payload, unsuccessful provider result retaining edits, unexpected exception not leaking private details, duplicate submit disabled while pending, and account switch during request not claiming another user's success. This is **mocked provider/widget acceptance**; it does not prove persistence by Supabase or a real second-device conflict. **12.07**, actual avatar upload and server authorization remain open.

### 13.05 — Position values (bounded)
`SportPositionsRegistry.getPositionsForSport` determines valid position codes. Save is rejected if the player's current selection is absent/invalid; owner saves do not send position. English/Arabic widget tests verify valid `FW`, invalid `UNVERIFIED`, and owner isolation. **13.02 / 13.03 / 13.04 / 13.06** remain open for real persisted position/preference editing and discovery propagation; the validation test is not that integration.
