# VSP Work Protocol — القواعد الدائمة

## اللغة
- تكلّم بالمصري دايماً.

## القاعدة الذهبية
- **ما تعدّلش سطر كود واحد إلا بعد موافقة المستخدم.**

## بروتوكول الـ 7 مراحل

### 1. 🔍 استكشاف (بدون موافقة)
- اقرأ الكود المتعلق وتتبع الـ flow كامل وافحص الـ side effects.

### 2. 🩺 تشخيص → رجّع تقرير مُنظّم
- 📍 المكان (ملف + سطر)
- 🔴 المشكلة (وصف دقيق)
- ⚠️ الخطورة (🔴 حرج / 🟠 عالي / 🟡 متوسط / 🟢 تحسين)
- 🔗 التأثير
- 💡 الحل المقترح (بالكلام بدون كود)
- 📊 قبل/بعد

### 3. ⛔ استنى الموافقة
- "نفّذ" → المرحلة 4
- "وضّح أكتر" → شرح إضافي → استنى تاني
- "لأ" / "غيّر" → عدّل الخطة → استنى تاني

### 4. ⚡ تنفيذ (بعد الموافقة بس)
- أقل تغيير ممكن (Minimal Change).
- ما تلمسش حاجة مالهاش علاقة.
- حافظ على كل الكومنتات الموجودة.

### 5. 🛡️ فحص ذاتي
- Regression check — التعديل ما كسرش حاجة تانية.
- Edge cases — null, empty, timeout, concurrent.
- Consistency — الأسلوب متوافق مع باقي الكود.

### 6. 📋 تسليم تقرير التنفيذ
- ✅ اللي اتعمل
- 📁 الملفات اللي اتعدلت (مع لينكات)
- ⚠️ انتبه لـ (أي ملاحظات)
- 🧪 نتيجة الاختبار

### 7. 🔄 مراجعة نهائية
- ملاحظات → نرجع نعدّل
- تمام → المهمة اللي بعدها

## قواعد عامة
- **أقل تغيير** — ما تعملش refactor أو تحسينات غير مطلوبة.
- **الدقة** — حدد الملف والسطر بالظبط دايماً.
- **الأمان أولاً** — أي تعديل RLS/SQL/Auth → تحذير 🔴 قبل التنفيذ.
- **ما تمسحش** — ما تحذفش كود/بيانات — soft-delete أو comment out بعد الموافقة.
- **اختبار** — شغّل `flutter analyze` بعد كل تعديل.
